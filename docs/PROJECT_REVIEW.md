# XploreSim 项目梳理与优化记录

## 项目边界

根目录是 2026 REBUILT 战术模拟器，使用原生 JavaScript ES Modules、Web Worker 和 Canvas，
没有运行时网络依赖，也不需要前端构建。`npm run serve` 在本机启动预览。
`reefscape/` 是独立 Git 仓库，根目录明确忽略它；两套模拟器均已纳入优化，分别维护和验证。
REEFSCAPE 的具体改动见其仓库内的 `OPTIMIZATION.md`。

## 核心数据流

1. `model.js` 提供机器人能力、阵容和场景；`rules.js` 集中保存规则常量。
2. `policy.js` 利用 `fastsim.js` 的近似模型搜索策略，`ai.js` 管理策略权重。
3. `engine.js` 用固定时间步模拟真实比赛过程，`mc.js` 聚合多场结果。
4. `worker.js` 执行耗时任务；`worker-client.js` 管理请求、进度、错误和取消。
5. `ui.js` 组织配置与结果；`viz.js` 绘制回放；`replay.js` 管理导出采样。

这个项目的优势是已具备引擎不变量、固定回放和多种策略测量脚本。
优化应先保证可复现性，再谈速度；规则参数或策略权重改变后，不能继续沿用旧测量结论。

## 本次落实的优化

| 方向 | 问题 | 修改 |
| --- | --- | --- |
| 稳定性 | Worker 崩溃后 Promise 不结束，按钮持续禁用 | 统一请求生命周期，拒绝等待请求并重建 Worker |
| 稳定性 | 计算中修改配置，结果与导出可能使用修改后的输入 | 启动时复制输入与上下文，成功后随结果保存 |
| 正确性 | 回放机器人标签、攀爬建议可能读取当前编辑阵容 | 使用该场比赛的阵容快照，并排除未上场机器人 |
| 正确性 | 小数场次数、空批次产生错误统计或非有限结果 | 校验引擎入口的场次数、搜索次数和阵营 |
| 性能 | 静态场地每帧重绘 | 按画布尺寸与像素比缓存，只重绘动态对象 |
| 性能 | 每帧重建 HUD 内容 | 按锚点更新数据，按状态变化更新阶段与 HUB 标记 |
| 回放 | 快速暂停/继续可能重复调度动画 | 集中管理启动、暂停和跳转，取消旧回调 |
| 回放 | 导入后“一秒跳转”按帧数计算，时长翻倍 | 按比赛时间定位 |
| 回放 | 重复导出不断减半帧数 | 按时间采样，保留端点，重复导出保持精度 |
| 体验 | 长计算无法中止 | 增加取消按钮，保留已有回放并支持重新计算 |
| 体验 | 标签页与阶段控件键盘行为不完整 | 增加键盘操作、可见焦点和无障碍语义 |
| 体验 | 初始播放速度与选择框显示不一致 | 初始化时直接读取选择框 |
| 可维护性 | Worker 通信与回放工具混在大 UI 文件中 | 拆分独立模块，使用 Node 原生测试验证 |
| 可移植性 | 静态检查手动解析 URL 路径 | 使用 `fileURLToPath` 支持带空格、中文的路径 |

## 验证方式

`npm run validate` 依次运行静态检查、运行时回归测试、引擎不变量、加分项档位审计（`npm run rp`）和 4 场固定回放比较。
`npm test` 可单独快速验证 Worker 恢复/取消、采样精度、输入边界、场地缓存、设置编解码与 scouting CSV 解析。

浏览器检查覆盖启动校准、计算中修改配置、快速播放/暂停、导出/导入、键盘导航，
以及取消后保留结果并重新计算。渲染耗时受浏览器、画布大小和设备影响；
静态缓存测试验证的是工作量减少，不把局部渲染测试等同于整个模拟器的加速比例。

## 后续架构边界

`ui.js` 仍集中承担较多展示逻辑，后续可按阵容编辑、结果面板、回放控制继续拆分。
这次没有调整物理模型、规则常量或策略权重；AI 胜率与模型校准仍应通过现有镜像、
消融和留出种子测试独立评估，不应由界面性能测试推断。

### 本轮验证方式

`npm run validate` 现在是 check + test(31) + verify + rp + golden(4 场)，全绿；三条已发布数字（greedy 镜像 591.7、AI 对 greedy 67.2%、三场 golden）未变——静音两条 FUEL 项对目标只是常数偏移（old−new 在 96 场里恒为 1.7000000000）。
浏览器走查用本机 headless Chromium 完成：自动保存与链接的往返、链接在已开标签页里生效、三类恶意字节各自被拒且页面仍能跑、AUTO 声明进引擎并在刷新后存活、CSV 导入的卡片就是下一场用的卡片。走查脚本留在 `.tmp/`（`browser-setup.mjs`、`browser-auto.mjs`、`browser-scouting.mjs`），因为它们需要本地浏览器，不进 `validate`。
守卫的“牙”用变异取证验过：把 `RP_TERMS.energized.live` 翻成 true 后 `npm run rp` 如期失败，把 `r.thresholds.supercharged.regional` 塞回 ui.js 后 `npm run check` 如期失败，两者均已还原。

### 仍未做的边界

赛事层（12 场资格赛的 RP 累计与排名、淘汰赛席位）没有做：单场分差仍是页面的判断单位，而真正要回答的是“进不进得去 playoffs”。它会直接继承本轮已知还偏差的两处（AUTO 吞吐与 TELEOP 5.36/s 对真实 4.7/s），做之前应先决定这些偏差在累计口径下如何披露。
`ui.js`（现 2.7k 行）与 `engine.js`（2.8k 行）的按面板/按子系统拆分仍是上界；本轮只把可独立测试的新模块（`chartdata.js`、`statestore.js`、`scouting.js`）拆了出去。
黄红牌在真实赛事里的跨场累积与 §6.6.3 的“红牌整条 alliance 适用”仍未建模，因为那需要赛事层先存在。
